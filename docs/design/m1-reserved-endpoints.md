# 经验卡片和可解释匹配

M1 先让两个账号完成问答、邀请、接受和消息。经验卡片和按语义重排的匹配留在这条链路之后，接口先占位。

经验卡片以后从一段双方都同意整理的问答起草。草稿记下原文、来源类型、适用阶段和它出自哪段问答。作者确认后才公开，并进入检索。在那之前，`/api/experience-cards` 与审核路径返回 `501 reserved`，不写入内容，也不把规则结果说成已经发布的卡片。

匹配目前只做同校同专业的精确筛选，响应 `source` 为 `rules`。以后在同一道问题上并列两组结果：只按学校和专业筛选的前几位，以及加上语义检索和关系重排的前几位。每组都写出来源。模型没有配置或调用失败时，只保留规则结果，并写明不是模型输出。两组结果留给以后的同题盲评，不在这一阶段宣称效果。
